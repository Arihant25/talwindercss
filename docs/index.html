Install

One stylesheet. Nothing to compile, nothing to configure.

<link rel="stylesheet" href="https://arihant25.github.io/talwindercss/dist/talwinder.min.css">

Then pick an art style on the root element:

<html lang="en" data-tw-art="ajrakh">

Without the attribute you get the default token set, which follows prefers-color-scheme and darkens to the raat palette at night.

The display faces are optional but the framework is designed around them:

<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Yatra+One&family=Rozha+One&family=Noto+Serif:wght@400;700&family=Kalam&display=swap">

How it works

There are three layers, and the middle one is the whole idea.

  1. Pigments are the raw named colours: --tw-haldi, --tw-sindoor, --tw-neel. They never change.
  2. Semantic tokens are roles: --tw-primary, --tw-surface, --tw-orn-ink, --tw-border-w. An art style is nothing but a block that reassigns these.
  3. Components read semantic tokens only. Not one component rule names a colour.

Because of that indirection, nine visually unrelated looks need zero component overrides, and adding a tenth style means writing one block of custom properties.

Scoping and nesting

data-tw-art is a plain attribute selector, so it works at any depth and the nearest ancestor wins. A page in one style can hold a section in another without a wrapper class or a specificity fight.

Chikankari inside

This card sets its own style. The page around it is truck art.

<div class="tw-card" data-tw-art="chikankari">
  <h4>Chikankari inside</h4>
  <button class="tw-btn tw-btn-primary">
    Nested
  </button>
</div>

Writing your own style

A style is a block of custom properties. Assign the semantic tokens and every component follows. You do not need to set all of them; anything you leave out falls through to the defaults in :root.

[data-tw-art="kalamkari"] {
  --tw-bg: #efe3c8;
  --tw-surface: #f7eed9;
  --tw-ink: #33241a;
  --tw-ink-soft: #6f5a45;
  --tw-primary: #7d2b1f;      /* the madder used on the cloth */
  --tw-on-primary: #f7eed9;
  --tw-accent: #b8892f;
  --tw-on-accent: #33241a;
  --tw-support: #2f5d52;
  --tw-line: #33241a;
  --tw-border-w: 2px;
  --tw-orn-ink: #7d2b1f;
  --tw-orn-opacity: .85;
}

Semantic tokens

These are what components read. Override any of them to retheme without touching a component rule.

TokenRole
--tw-bgPage ground. --tw-bg-image holds an optional gradient wash.
--tw-surfaceRaised surfaces: cards, nav, table body.
--tw-surface-2A second surface for contrast within a card.
--tw-inkBody text. --tw-ink-soft for secondary, --tw-ink-inv for text on dark.
--tw-primaryMain action colour. Pair with --tw-on-primary.
--tw-accentDefault button fill, table headers, hoarding. Pair with --tw-on-accent.
--tw-supportThird colour, for signboards and tertiary actions.
--tw-lineBorder colour. --tw-line-soft is the same at 25% for internal rules.
--tw-border-wBorder weight. Truck art sets 4px, chikankari sets 1px.
--tw-shadowOffset shadow. Also -sm, -lg, -soft.
--tw-orn-inkColour every ornament mask is painted in. --tw-orn-opacity and --tw-orn-scale tune it.

Raw pigments

Available whatever the style. Use them when you want a specific colour rather than a role: var(--tw-haldi), --tw-marigold, --tw-saffron, --tw-kesari, --tw-sindoor, --tw-lal, --tw-manjistha, --tw-gulaal, --tw-rani, --tw-mehndi, --tw-tulsi, --tw-mor, --tw-peacock, --tw-neel, --tw-jamun, --tw-baingan, --tw-chai, --tw-geru, --tw-multani, --tw-sona, --tw-tamba, --tw-cream, --tw-kajal.

There is also .tw-tiranga and .tw-tiranga-h, which use the flag's exact specified colours in correct thirds.

Spacing

A 4px scale from --tw-s1 (4px) to --tw-s24 (96px), exposed as tw-p-*, tw-px-*, tw-py-*, tw-mt-*, tw-mb-* and tw-gap-*. For vertical rhythm inside a container, tw-stack puts a gap between every child after the first.

Recolouring and resizing

Set the two variables locally. Nothing else needs to change.

<div class="tw-pattern-ajrakh"
     style="--tw-orn-ink: var(--tw-jamun);
            --tw-orn-scale: .6"></div>

A mask replaces any other mask on the same element. To fade a pattern out, put the fade on a wrapper and the pattern on a child.

Overlays

tw-orn-* puts the motif behind an element's own content instead of replacing it. Add tw-orn-faint or tw-orn-strong to change the weight.

Layout

tw-grid-auto fits as many columns as will hold their minimum width, set per instance with --tw-min. No breakpoints needed.

<div class="tw-grid-auto" style="--tw-min: 280px">
  <div class="tw-card">…</div>
  <div class="tw-card">…</div>
</div>

Fixed grids tw-grid-2 through tw-grid-4 collapse to two columns under 900px and one under 640px. Flex helpers: tw-flex, tw-col, tw-wrap, tw-items-center, tw-justify-between, tw-grow. Containers: tw-container, tw-container-sm, tw-container-lg.

Motion

tw-reveal and tw-draw-kolam are driven by scroll position through animation-timeline: view(), not by a timer or an observer. They sit behind an @supports guard, so in a browser without scroll-driven animations the content is simply visible.

<div class="tw-pattern-kolam tw-draw-kolam"></div>

<div class="tw-reveal">fades up on entry</div>
<div class="tw-hover-lift">lifts on hover</div>
<div class="tw-bob">bobs</div>
<div class="tw-sway">sways, for hanging things</div>

Every animation in the framework is switched off under prefers-reduced-motion: reduce.

Indic scripts

Devanagari, Tamil, Bengali and Gurmukhi hang glyph parts above and below the headline stroke. A Latin-tuned line-height clips the matras. The base stylesheet gives any element matching :lang(hi), :lang(ta), :lang(bn) and the rest a taller line-height, so tagging your markup correctly is enough.

Accessibility

  • Each style's --tw-on-primary, --tw-on-accent and --tw-on-support are chosen to clear WCAG AA against their fill.
  • Focus is never removed. :focus-visible gets a 3px accent outline with offset, on every interactive element.
  • All motion stops under prefers-reduced-motion: reduce.
  • Ornaments are decorative. Mark them aria-hidden="true"; the framework does not do it for you because only you know whether a given strip is meaningful.
  • tw-sr-only hides content visually while leaving it for screen readers.

Browser support

The framework needs CSS custom properties, mask-image and color-mix(). That is Chrome 111, Edge 111, Safari 16.2 and Firefox 113 and later.

Two features degrade rather than break. Scroll-driven animation sits behind @supports (animation-timeline: view()), so elsewhere the content is just visible. @property makes the zari shimmer smooth; without it the gradient still renders, it simply does not animate.
